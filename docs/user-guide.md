# 터치라인 · FC 27 커리어 스쿼드 빌더

한글 스쿼드 빌더와 OpenAI 대화를 함께 사용하는 개인용 도구입니다. **AI를 사용하려면 `시작.cmd`를 더블클릭**하세요. 브라우저에서 `http://127.0.0.1:4267`을 열고, 내 PC에서만 접속할 수 있는 서버가 실행됩니다.

저장한 선수로 스쿼드를 구성하거나 스탯을 계산할 때는 `index.html` 하나를 직접 열어도 됩니다. 선수 데이터 API 검색과 AI 축구 상담은 `시작.cmd`로 열어주세요.

## AI 첫 실행

1. 프로젝트 폴더의 `.env`를 열고 `OPENAI_API_KEY=` 뒤에 본인의 OpenAI API 키를 직접 붙여넣고 저장합니다. 키를 대화창이나 HTML에 입력하지 마세요. `.env`가 없다면 `.env.example`을 복사해 만드세요.
2. `시작.cmd`를 더블클릭합니다. Node.js가 있으면 사용하고, 이 PC의 Codex에 포함된 Node.js도 찾아 사용할 수 있습니다. 둘 다 없으면 Node.js 20 이상이 필요합니다.
3. `AI 축구 상담` 탭에서 대화를 시작합니다. 이미 열어뒀다면 `연결 확인`을 누르면 새로 저장한 키를 읽습니다. 키만 변경할 때 서버를 다시 실행할 필요는 없습니다.
4. 사용을 마치면 `종료.cmd`를 실행해 로컬 서버를 끌 수 있습니다. 브라우저를 닫는 것만으로는 서버가 꺼지지 않습니다.

기본 설정은 `OPENAI_MODEL=gpt-6-luna`, `OPENAI_REASONING_EFFORT=medium`입니다. 이 앱의 선수 검색·추천·계산은 기존 기능이 수행하고, LLM은 요청 해석과 기능 선택·결과 설명을 담당하므로 비용을 우선해 Luna로 시작합니다. Terra와 비교하려면 `.env`에서 모델만 `gpt-6.1-terra`로 바꾸세요. 이는 앱에서 호출할 모델 설정이며 Codex 자체의 모델 설정을 바꾸지 않습니다. 계정에서 해당 모델을 사용할 수 없으면 안내를 표시하고 멈추며, 다른 모델로 자동 변경하지 않습니다. 추론 수준은 low, medium, high, xhigh, max를 지원합니다. 포트를 변경했다면 서버를 종료하고 다시 시작하세요.

2026-11-08 확인한 [공식 API 가격표](https://developers.openai.com/api/docs/pricing)의 Standard·짧은 문맥 기준으로 GPT-6 Luna는 입력 100만 토큰당 $0.10, 출력 $0.50이며, GPT-6.1 Terra는 입력 $1.00, 출력 $5.00입니다. 같은 비캐시 입력·출력 토큰 수라면 Luna의 단가는 Terra의 10분의 1입니다. 대화 한 번에도 여러 번 모델을 호출할 수 있으므로 실제 비용은 전체 입력·출력과 추론 토큰, 캐시 사용에 따라 달라집니다. 이 앱에서 두 모델의 실제 품질 비교는 API 키 입력 후 같은 요청으로 확인해야 합니다.

키를 새로 만들려면 [OpenAI API 키 페이지](https://platform.openai.com/api-keys)에 로그인하고 사용할 프로젝트에서 새 비밀 키를 생성하세요. 이름은 `fc27-squad`처럼 알아보기 쉽게 지정하면 됩니다. 발급된 값을 `.env`의 `OPENAI_API_KEY=` 뒤에 저장하세요. 키와 모델 선택은 별개입니다. 기존 키가 유효하고 해당 프로젝트에 모델 사용 권한이 있다면 모델을 바꾸려고 키를 새로 발급할 필요는 없습니다. 키를 교체할 때는 새 키로 연결을 확인한 후 이전 키를 폐기하세요.

OpenAI API 사용량에는 질문 분류, 답변, 필요한 웹 검색이 포함됩니다. 분류 요청에는 현재 질문과 최근 대화를 보냅니다. FC27 기능을 쓰는 답변에는 스쿼드 요약과 도구에 필요한 선수 정보를 추가합니다. 웹 검색 요청은 공개 사실을 묻는 별도 질문으로 보냅니다. 선수 사진·사진 주소·감독 노트·선수 메모는 제외합니다. API 키는 로컬 서버의 인증에만 사용합니다. OpenAI 요청은 `store: false`로 보내며, 서비스 측 데이터 처리 조건은 본인의 API 계정 정책을 따릅니다. 앱의 대화 기록은 서버와 현재 창의 메모리에만 보관합니다.

**기존 HTML과 시작.cmd의 주소는 브라우저 저장 공간이 다릅니다.** 기존 창에서 `백업 저장`을 누른 뒤 새 화면의 `선수 데이터`에서 그 JSON을 가져오면 선수·사진·스쿼드를 옮길 수 있습니다. 사용하는 브라우저를 바꾸는 경우에도 같은 방식으로 옮기세요.

## 대화로 할 수 있는 일

- “오늘 K리그1 경기 일정이랑 중계 알려줘.” → 공개 자료를 검색하고 날짜와 출처를 답변에 표시합니다.
- “풋살에서 픽소가 전진하면 뒤는 누가 메워?” → 실축과 풋살의 전술·규칙·역사·훈련을 설명합니다.
- “펨에서 볼위닝 미들이랑 앵커는 뭐가 달라?” → 축구 게임별 역할·전술·조작을 상담합니다. 최신 패치나 버전별 조작은 공개 자료로 확인합니다.
- “왼쪽 센터백은 볼플레잉 수비수, 포커스는 빌드업으로 잡아줘.” → 현재 스쿼드의 해당 자리에 적용할 FC IQ 역할 변경안을 준비합니다.
- “4-2-3-1로 점유율이 높은 유망주 팀을 짜줘.” → 선수 DB와 내 선수 목록을 평가해 **스쿼드에 적용**할 변경안을 준비합니다.
- “4-2-3-1과 4-3-3의 장단점을 비교해줘.” → 포메이션과 전술을 비교합니다.
- “정석 4-2-3-1이랑 사파 3-2-4-1을 비교해줘.” → 같은 스쿼드의 정석 배치와 변칙 배치를 비교합니다. 이어서 “그럼 사파로”나 “정석으로 다시”처럼 방향을 바꿀 수 있습니다.
- “현재 포메이션에서 내 목록의 선수를 CM에 배치하면 어때?” → 추가한 선수의 이름을 넣으면 배치 적합도를 살펴볼 수 있습니다.
- “챔피언십에서 시작할 건데 포텐 높은 유망주 위주로 가고 싶어. 이강인은 CM으로 기용할 거야.” → 로컬 DB에서 선수를 찾고 커리어 팀 구성과 기용 방향을 상담합니다.
- “스토크로 시작해. 첫 시즌에는 현실적인 영입으로 유망주 선발을 짜줘.” → 구단의 현재 전력과 리그를 기준으로 잔류할 선수, 영입 및 임대 문의 후보를 나눕니다. 같은 대화에서 “승격한 뒤 보강 후보는?”처럼 단계를 바꿔 볼 수 있습니다.
- “이강인의 OVR랑 잠재력을 알려줘.” → 로컬 선수 DB에서 찾은 값을 확인합니다.
- “PS5에서 감아차기는 어떻게 해?” → 게임 조작과 경기 플레이를 상담합니다.
- “음바페의 플레이스타일+는 뭐야?” → 선수 DB에서 일반 플레이스타일과 +를 나누어 확인합니다.
- “퀵 스텝+ 있는 23세 이하 선수를 찾아줘.” → 플레이스타일 등급과 나이 조건을 함께 검색합니다.
- “이강인을 CM에서 OVR 82로 맞추려면?” → 목표 스탯 변경안을 계산기로 엽니다. 포지션별 OVR는 계획용 추정치입니다.

분류기는 은어·오타·별명과 “그럼 거기는?”처럼 앞 대화를 잇는 표현을 함께 해석합니다. 축구와 무관한 별도 요청이나 내부 설정 접근 요청은 분류 단계에서 종료합니다. 팀·선수·게임이 모호하면 맥락을 확인합니다. FC27 수치와 실축·다른 게임의 자료는 구분해서 답합니다. 추천은 적용 버튼을 눌러 반영하며, 고정된 선수의 자리와 포메이션을 유지합니다. 적용한 변경은 실행 취소할 수 있습니다.

구단 커리어 추천은 적재된 각 구단의 상위 OVR 11명과 리그 전력을 참고합니다. 장기 목표가 있어도 시작 단계는 첫 시즌입니다. 승격·안착이나 유럽대항전 진출 이후를 지정하면 영입 후보 범위가 넓어집니다. 첫 시즌에는 기존 선수와 국내 시장을 우선하며, 상위 전력 구단의 어린 로테이션 후보는 임대 문의로 표시합니다. 직접 지정한 선수는 예외가 될 수 있습니다. 실제 이적 의사, 출전 시간, 이적료와 주급은 게임 세이브에서 확인하세요. 창에 **연결 흐름 테스트 · 실제 AI 아님**이 표시되면 개발 검증용 응답입니다. `node server.cjs --mock`은 선수 검색과 AI 상담 모두 모의 응답을 사용합니다. 표시되는 임시 주소를 브라우저에서 열면 기존 스쿼드의 저장 주소와 분리된 상태로 시험할 수 있습니다. 일반 실행은 `시작.cmd`를 사용하세요.

## 사용

- 경기장 자리를 클릭하고 선수 목록의 + 버튼으로 배치합니다. 선수 목록에서 경기장으로 드래그할 수도 있습니다.
- 다른 선수 위로 드래그하면 교체합니다. 빈 경기장으로 드래그하면 좌표와 자리의 포지션을 조정합니다. 세부 포지션은 선수 정보에서 직접 지정할 수 있습니다.
- 자물쇠는 **추천 시 고정**입니다. 고정 선수가 있으면 추천은 현재 포메이션과 위치를 유지합니다. 수동 이동·포메이션 변경은 가능합니다.
- **선수 역할**에서 선발 자리, 역할, 포커스를 고른 뒤 **이 자리에 저장**을 누르세요. 같은 포지션의 왼쪽과 오른쪽 자리에 서로 다른 역할을 줄 수 있습니다. 설정은 스쿼드별로 자동 저장되고 JSON 백업에 포함됩니다. 선수 교체 시에는 자리의 역할을 이어받고, 포메이션을 바꾸면 같은 포지션의 가까운 자리로 설정을 옮깁니다. 자리의 포지션을 직접 바꾸면 그 포지션에서 가능한 조합을 유지합니다. [EA FC IQ 역할표](https://www.ea.com/games/ea-sports-fc/fc-25/news/pitch-notes-fc-25-fc-iq-deep-dive) · [EA 역할·포커스 업데이트](https://www.ea.com/games/ea-sports-fc/fc-26/news/pitch-notes-fc26-gameplay-deep-dive) · [EA FC 27 선수 역할 안내](https://www.ea.com/games/ea-sports-fc/fc-27/news/fc-27-closed-beta-feedback-update)
- `내 스쿼드`에서 새 스쿼드를 만들거나 복제·전환합니다. 브라우저 자동 저장과 전체 JSON 백업·복원을 지원합니다.
- `선수 데이터`에서 JSON·CSV를 불러오거나 선수를 추가·수정합니다. 사진은 HTTPS 주소 또는 PC 파일로 지정할 수 있습니다. 업로드 이미지는 최대 256픽셀로 줄여 백업에 포함합니다.
- **선수 추천 → 스카우팅**에서 감독 구단과 예산, 보강할 자리, FC IQ 역할을 골라 후보를 찾습니다. 보고서를 관심 명단에 저장하거나 선수 2~3명을 비교하고, **이적 협상**에서 이적료·분할 지급·주급·임대 조건과 협상 상태를 기록할 수 있습니다.
- **유망주 육성**은 현재 OVR와 POT 차이, 전성기까지 남은 시간, 선택한 육성 기간과 전성기의 겹치는 기간을 함께 봅니다. 선수 검색과 **성장 전망**에서 FC27 기본 로스터에 연결된 성장 유형을 자동으로 표시합니다. 세이브에서 확인한 성장 유형과 POT를 기록하면 그 값을 우선합니다. [FC27 기본 로스터 데이터](https://github.com/ViniMacacari/eafc-db-kit/tree/1464907bf4e726504d8b3ce15ffd0a552990565e/templates/FC%2027) · [CMTracker 전성기 분석](https://news.cmtracker.net/)
- **사파 전환 보고서의 커버 추천**은 실제 선발·후보와 배치할 자리를 확인합니다. 커버 기준에 부족하면 구단 현실성, 영입 조건, 전환 선수와 커버 후보의 합계 영입비·주급을 비교해 최대 3명을 표시합니다. 커버 기준은 핵심 능력치와 기록된 출전 상태로 판단하는 앱의 전술 추정입니다.
- **기용 방식 → 사파 전환만**에서 선호 포지션 밖의 후보를 찾습니다. **사파 전환** 보고서는 포지션 OVR 변화, 추천 역할과 포커스, 필요한 커버를 보여줍니다. 전환안을 관심 명단에 저장하거나 보드의 해당 자리에 시험 배치할 수 있습니다.
- **스태프와 성장**에서 부서별 수석 코치와 이적·유스 스카우트의 별 등급을 기록합니다. 같은 포지션의 기준 OVR 평가가 두 건 이상 있으면 기록된 변화 속도를 기준으로 성장 전망을 추정합니다. 스카우트 보고서, 협상, 스태프는 스쿼드별로 자동 저장하고 JSON 백업에 포함합니다.
- **선수 추천 → 스쿼드 구성**은 팀 스타일과 육성 방향에 맞춰 선발과 후보를 제안합니다. 고정한 선수는 현재 자리를 유지합니다. 스카우팅·스쿼드 구성·AI 추천은 성장 유형, 전성기, 육성 기간, 세이브 평가와 FC IQ 역할을 같은 계산으로 평가합니다. 전체 배치는 자리별 역할과 선수 중복을 함께 고려합니다.
- **스쿼드 전체 예산**에 총 영입 예산과 선수단 전체 주급 한도를 입력하면 사파 선수와 커버 선수를 함께 배치하는 영입 조합을 계산합니다. 신규 선수의 이적료는 한 번씩 합산하고, 주급은 기존 선발·후보·예비와 감독 구단 소속 선수 전체에 신규 영입을 더합니다. 저장 목록에만 있는 선수는 소유 선수로 간주하지 않습니다. 후보·예비는 기존 선수로 채웁니다. 매각 계산을 켜지 않으면 방출과 매각 수입을 가정하지 않습니다. 스카우팅의 1인 예산 및 추가 주급 여력과 별도의 한도입니다. 빈칸은 해당 한도 없음, 0은 추가 이적 지출 없음/전체 주급 0입니다.
- 결과에는 **합계·잔여 예산, 영입 명단, 사파/커버 동시 배치, 대안 조합**을 표시합니다. 시장가·DB 주급보다 같은 통화로 기록한 예상 이적료·주급을 우선합니다. 한도가 있는 비용이 미확인이면 제외하고, 기존/고정 선수 비용이 미확인이거나 매각까지 고려해도 예산을 넘으면 계산을 중단합니다. 한 커버 선수를 공유할 때 중복 비용을 붙이지 않으며, 커버는 자연 포지션·실제 역할·출전 상태까지 확인합니다. 고정되지 않은 자리의 역할은 필요한 커버에 맞게 제안할 수 있습니다. 탐색은 점수와 저비용 후보를 함께 추린 제한 탐색이므로 전역 최적해를 보장하지 않습니다. 완성 조합이 없으면 미완성 및 빈자리를 명시합니다. 실제 협상 가격·미입력 보너스·게임 내 경기 결과는 보장하지 않습니다.
- **방출·매각 후보와 수익까지 함께 계산**을 켜면 매각과 영입을 함께 비교합니다. 기본 최대 매각은 3명, 예상 수령액은 DB 시세의 80%, 영입 재투입률은 100%이며 직접 바꿀 수 있습니다. 선수 보고서의 **예상 매각 수령액(수수료 차감 후)**이 같은 통화로 저장돼 있으면 그 값을 우선합니다. 가용 영입 예산은 기존 예산 + 예상 수령액 × 재투입률, 최종 주급은 기존 주급 − 매각 선수 주급 + 신규 주급입니다. 고정 선수와 최종 선발·커버는 팔지 않으며, 선수단 18명(기존 18명 미만이면 기존 규모)과 기존에 확보한 골키퍼 최대 2명을 보호합니다. 전력과 선수층 손실도 비교해 불필요한 매각을 줄입니다. **매각 성사 가정**을 결과에 명시하며 실제 선수 삭제, 이적 성사 기록 또는 예산 정산은 하지 않습니다. 계약 해지 방식의 방출은 해지금 정보가 없어 계산하지 않습니다.
- AI 상담의 **원하는 장단점에 맞춘 스탯 변경안**은 선수 검색 후 실제 계산 도구로 만듭니다. “아스톤빌라의 마조를 중미·총스탯 89, 빠르고 패스는 못하는 피지컬형으로”처럼 말하면 구단·선수를 확인하고 목표 CM·OVR 89와 능력치 조건을 전달합니다. 빠른 피지컬/패스 약점 유형의 기본 기준은 가속·속력·힘 90 이상, 스태미나·점프·적극성 85 이상, 짧은 패스·시야·크로스 55 이하, 긴 패스 50 이하입니다. 구체적 수치를 지정하면 능력치별 하한·상한이 우선하며, 현재값 유지는 하한=상한으로 계산합니다. 목표가 불가능하면 **도달 가능 범위와 상한의 영향**, 별도의 상한 완화 예시를 보여줍니다. 원래 조건을 몰래 바꾸지 않으며 계산기와 JSON 변경안에도 같은 조건을 전달합니다. 게임 내부 편집·성장 결과를 보장하지 않는 추정입니다.
- `스탯 계산기`는 12개 포지션별 OVR와 증감을 비교하고, 가중치 변화에 따른 스탯별 기여도를 보여줍니다. 목표 OVR에 대한 세 가지 스탯 변경안을 별도 JSON으로 내보낼 수 있습니다. 선수 원본과 실제 게임은 바꾸지 않습니다.
- 선수 카드의 큰 숫자는 배치한 포지션의 OVR 추정으로 바뀝니다. 주 포지션은 입력 OVR를 표시하며, 다른 포지션은 `OVR 추정`과 원래 OVR 대비 증감을 함께 표시합니다. 세부 스탯이 없으면 수치를 만들어내지 않고 `—`를 표시합니다.

자동 저장은 브라우저와 HTML 파일 위치에 영향을 받습니다. 중요한 데이터는 `백업 저장`으로 보관하세요. 외부 사진 주소는 주소만 백업하므로 표시할 때 인터넷이 필요합니다. 업로드한 사진은 백업에 포함됩니다. 실행 취소 기록은 현재 창에서만 유지됩니다.

## 데이터 범위와 추정

새 목록은 빈 상태로 시작합니다. 이전 저장에서 기본 예시 선수와 해당 선수의 배치만 정리하며, 직접 입력하거나 API·파일로 가져온 선수는 보존합니다. 빈 나이·POT·세부 스탯은 미입력 상태로 표시합니다.

프리셋 29종은 2026-11-08 확인한 [FIFACM FC 27 커리어 빌더](https://www.fifacm.com/squad-builder)의 목록과 번호를 참고하고, [FUT.GG](https://www.fut.gg/tactics/)의 명칭을 대조했습니다. 좌표는 이 도구를 위해 구성한 것으로, PS5 게임의 모든 실제 좌표와 대조하지 않았습니다. 수동 변경한 포지션은 자유 배치로 표시합니다.

배치 가능한 12포지션의 가중치는 2026-09-19 FC27 선수 19,789명의 공개 OVR로 학습한 FCCareer 계수를 사용합니다. 출처와 포지션별 표본 수, 제공처 보고 MAE는 계산기에 표시합니다. [FCCareer FC27 계산기](https://www.fccareer.ai/calculators/player-rating)

`LF`는 2026-11-03 FCRadar 로컬 스냅샷의 LF 선수 537명으로 가중치를 별도 학습했습니다. 비음수·합계 100% 조건으로 맞췄고, 5겹 교차검증에서 주 포지션 OVR 평균 절대 오차는 0.32였습니다. 이강인처럼 원본 포지션이 LF인 선수도 그 기준으로 다른 자리의 OVR를 추정할 수 있습니다. 가중치 전체표의 CSV·JSON에 LF와 학습 출처를 포함합니다.

**이 수치는 EA의 공식 계수표나 PS5 게임 검증값이 아닙니다.** 제공처의 MAE는 주 포지션 선수 표본에 대한 오차로, 타 포지션 전환 오차의 보장 범위가 아닙니다. 독립된 실제 FC27 커리어 데이터로 검증하지 않았습니다. 해당 사이트의 LWB·RWB 모델은 별도 표본이 없고 LB·RB를 복사한 것이므로 FC27용 별도 포지션으로 추가하지 않았습니다.

```text
포지션 점수 = 관련 세부 스탯의 가중 평균
전환 OVR 추정 = 입력 OVR + 목표 포지션 점수 - 주 포지션 점수
변경 후 추정 = 입력 OVR + 변경 후 목표 포지션 점수 - 변경 전 주 포지션 점수
```

실제 게임의 체형·플레이스타일·약발·개인기·성장·내부 보정·POT 제한은 반영하지 않습니다. 관련 스탯이 없으면 계산을 중단하고 누락 항목을 표시합니다. 추천에는 세부 스탯이 없는 선수도 OVR·포지션 중심으로 참여할 수 있으며 이유에 이를 표시합니다.

[EA 공식 FC27 커리어 설명](https://www.ea.com/games/ea-sports-fc/fc-27/news/pitch-notes-fc27-career-mode-deep-dive)은 포지션별 Baseline OVR, 최대 7개 선호 포지션, 폼·사기·경기 체력에 따른 Dynamic OVR를 설명합니다. 이 도구는 **세부 스탯을 고정한 포지션별 기준 OVR 비교**만 추정하며, 실제 비선호 포지션 페널티와 Dynamic OVR의 비공개 보정은 적용하지 않습니다. 스탯별 기여도는 `(스탯 - 주 포지션 점수) × (목표 가중치 - 주 가중치)`로 분해하며, 전체 합은 상하한·표시 반올림 전 포지션 점수 차이와 일치합니다.

선수 검색과 OpenAI 상담은 `.env`의 키를 읽는 로컬 서버를 통해 연결합니다. 직접 등록하거나 가져온 선수를 사용할 수 있습니다. PS5 세이브 동기화와 게임 에디터 자동 적용은 지원 범위 밖입니다.

## 개발 파일

기본 스쿼드 기능은 `index.html`만으로 사용할 수 있습니다. AI를 사용할 때는 시작·종료 파일과 `server.cjs`, `server/`, `src/`, `tools/`를 포함한 프로젝트 폴더를 유지하세요. `.env`는 본인 PC에 보관하고 공유하지 마세요.

| 파일 | 용도 |
|---|---|
| `src/core.js` | 포메이션, 가상 선수, 배치, 최적 할당, 추천, 추정, 백업 검증 |
| `src/fc-iq.js` | 포지션별 FC IQ 역할과 포커스 |
| `src/rating-model.js` | 출처·날짜·표본 수가 포함된 FC27 DB 학습 가중치. EA 공식 산식 아님 |
| `src/data-adapter.js` | JSON·CSV 입력과 추후 허용된 API 응답 변환 경계. 네트워크 호출 없음 |
| `src/app.js` | 화면, 드래그, 사진 업로드, 파일 백업·복원, 브라우저 저장 |
| `src/ai-chat.js` / `src/ai-context.js` | 대화 화면, 결과 적용, 사진·메모를 제외한 대화용 데이터 |
| `server.cjs` / `server/` | 로컬 서버, `.env` 읽기, OpenAI Responses 호출, 기능 입력 검증 |
| `src/style.css` / `src/template.html` | 디자인과 HTML 구성 |
| `tools/build.cjs` | 원본을 독립 실행 가능한 HTML로 묶기 |
| `tools/launch.cjs` / `tools/node.cmd` | 서버 시작·종료와 Node.js 찾기 |

| `qa/` | 브라우저 확인에 사용한 가상 자료와 결과 화면 |

Node.js가 있는 개발 환경에서는 별도 패키지 설치 없이 실행합니다.

```powershell
npm run build
npm test
npm start
npm stop
```

OpenAI 연결은 Responses API를 사용합니다. 질문 분류 1회에 이어 필요한 경우 공개 웹 조회를 실행합니다. 웹 조회 응답에는 검색 도구 호출을 최대 3회 허용합니다. FC27 계산 답변은 최대 5회 응답과 12회 로컬 기능 호출을 사용하며, 호출 이름과 입력값을 서버에서 검증합니다. 전체 요청의 시간 한도는 120초입니다. 다섯 번째 FC27 응답은 결과를 정리하고, 응답이 끊기면 확인한 선수와 계산한 변경안을 표시합니다. [OpenAI 웹 검색 안내](https://developers.openai.com/api/docs/guides/tools-web-search) · [공식 기능 호출 안내](https://developers.openai.com/api/docs/guides/function-calling)

## 선수 DB와 검색

`시작.cmd`로 연 **선수 검색**에는 현재 적재된 FC27 스냅샷의 날짜와 선수 수가 표시됩니다. 전체 DB는 `data/fc27-players.json`에 저장되고 서버 재시작 후에도 읽어옵니다. 새 스냅샷은 **스냅샷 갱신**으로 확인합니다. 적재가 중단되면 다음 실행에서 같은 스냅샷의 마지막 저장 페이지부터 이어받고, 갱신 중에는 직전 완성본으로 검색할 수 있습니다.

승인받은 CMTracker 데이터는 `data/cmtracker-growth-profiles.json`으로 가져올 수 있습니다. 형식은 `{"game":"FC27","version":1,"provider":"cmtracker","players":[{"playerId":243780,"growthProfile":"Default"}]}`입니다. `snapshot`(YYYYMMDD)과 선수 페이지의 `url`을 함께 기록할 수 있습니다. 서버를 재시작하면 일치하는 EA 선수 ID에 CMTracker 값을 우선 표시합니다. [CMTracker API 접근 신청](https://cmtracker.net/api-access)

**선수 상세**에서 전용 페이지로 이동합니다. 키·몸무게와 포지션, OVR·POT, 세부 능력치, 플레이스타일을 확인하고 스쿼드 자리를 고를 수 있습니다. 스탯은 90–99, 80–89, 70–79, 60–69, 1–59 구간으로 표시합니다. 플레이스타일 배지에 마우스를 올리거나 키보드 포커스를 옮기면 효과 설명이 나타납니다. **선수 검색으로** 또는 브라우저 뒤로 가기를 누르면 기존 검색 결과로 돌아갑니다.

생년월일과 실제 소속 이력은 공개 Wikidata 항목의 선수 이름·나이·국적이 일치할 때 상세 페이지에 표시합니다. 기록에서 확인된 기간과 팀을 보여주며, 데이터가 없는 경우에는 미확인으로 표시합니다. [Wikidata 소속 팀 항목](https://www.wikidata.org/wiki/Property:P54) · [EA 플레이스타일 안내](https://www.ea.com/games/ea-sports-fc/fc-27/news/what-are-playstyles)

스타일 추천과 AI 축구 상담의 FC27 기능은 로컬 DB와 개인 선수 목록을 함께 사용합니다. 추천이나 배치안을 적용할 때 필요한 선수만 개인 스쿼드에 저장합니다. 직접 편집한 선수는 같은 ID의 DB 선수보다 우선합니다.

`시작.cmd`로 연 화면의 **선수 검색**에서 이름과 조건을 넣고 검색하세요. 결과의 선수 ID를 FC 온라인 공개 목록과 대조해 일치하는 한글 이름과 원래 이름을 함께 표시합니다. `비니시우스 JR`는 요청한 표기를 적용합니다. 등록된 별칭은 그대로 쓸 수 있고, 별칭이 없는 한글 이름은 FC 온라인 목록의 전체 이름으로 검색할 수 있습니다. 일치하는 선수가 없거나 공개 목록 연결이 안 되면 기존 별칭과 원래 이름을 사용합니다. [FC 온라인 메타데이터 안내](https://openapi.nexon.com/ko/game/fconline/?id=5)

**상세 검색**에서 남자·여자, 리그, 해당 리그 소속팀, 국적을 목록에서 선택할 수 있습니다. 나이·POT·키·몸무게는 최소와 최대를 지정합니다. 조건은 적재된 DB 전체에 적용되고 페이지당 최대 25명을 표시합니다. 남자·여자 분류는 FCRadar 리그 분류를 사용합니다. 분류가 확인되지 않은 선수는 전체 검색에서 볼 수 있습니다.

DB 적재와 실시간 검색에는 승인된 `FCRADAR_API_KEY`, 실제 상담에는 유효한 `OPENAI_API_KEY`가 필요합니다. `OPENAI_MODEL`에는 API 계정에서 사용할 수 있는 모델을 지정하세요. DB 검색과 스타일 추천은 로컬 서버에서 계산합니다. AI 상담은 현재 스쿼드 요약과 해당 기능에 필요한 검색·분석 결과를 모델에 보냅니다.

FCRadar의 승인 범위에서 선수 데이터와 이미지를 사용하세요. 개인 스쿼드 빌더에서 선택한 선수를 로컬에 저장하고, AI 상담에 필요한 선수 정보를 OpenAI로 보낼 수 있는지 승인 범위를 확인하세요. [FCRadar API 이용약관](https://fcradar.gg/api-terms)

사진을 표시하려면 [API 접근 페이지](https://fcradar.gg/my-account/api-access)에서 계정에 발급된 `image_cdn_base_url`을 확인하고 `.env`의 `FCRADAR_IMAGE_CDN_BASE_URL`에 추가하세요. 이 이미지 주소는 API 비밀 키와 따로 발급됩니다. 사진 제공 선수는 검색 결과와 카드에 표시됩니다. 이미 저장한 선수를 다시 추가하면 빈 사진과 API 한글 이름을 보완합니다. 직접 수정한 이름을 보존합니다. [FCRadar 이미지 CDN 안내](https://fcradar.gg/api-pricing#cdn)

- 공식 [FCRadar 개발 문서](https://fcradar.gg/developers)와 [OpenAPI 스키마](https://pub-api.fcradar.gg/public-api/docs?public-api-docs.json)를 확인했습니다. 스키마 사본: `research/fcradar-openapi.json`.
- 서버에서 FCRadar의 활성 스냅샷을 확인하고 해당 날짜를 고정해 최대 100명씩 받습니다. 같은 스냅샷의 완성본이 있으면 상태만 확인합니다. FC 온라인 공개 이름 목록은 별도 인증 없이 읽고 서버 메모리에 하루 동안 보관합니다.
- 이름, 포지션, OVR, POT, 나이, 팀, 국적, 상세 스탯과 일반 플레이스타일(`playstyles`), 플레이스타일+(`playstyle_plus`)를 가져옵니다. 검색 결과는 은색·금색 아이콘을 구분하고 상세 화면은 한국어 이름과 등급을 보여줍니다. 아이콘은 FCRadar 선수 페이지의 이미지를 사용하며 연결이 끊기면 텍스트 배지가 표시됩니다. 사진은 CDN 설정과 선수별 제공 여부에 따라 표시합니다. 역할, 시세와 임금은 현재 지원 범위 밖입니다.
- 예전 스냅샷은 계속 검색할 수 있습니다. 플레이스타일과 리그·신체 정보를 채우려면 **스냅샷 갱신**을 누르세요. 적재 중에는 기존 스냅샷을 사용하고, 모든 페이지를 확인한 뒤 새 파일로 교체합니다.
- 스냅샷의 전체 행 수와 각 페이지의 수신 건수를 대조합니다. 필수 정보가 빠진 행과 중복 ID는 적재 화면에서 제외 건수로 표시합니다.
- LS·RS는 ST로 표시합니다. LF처럼 가중치가 없는 원본 주 포지션은 포지션과 OVR를 보존하고, 다른 자리에 배치했을 때 전환 OVR를 빈 값으로 표시합니다.
- 포지션 계산은 기존 FCCareer 계수 기반 추정입니다. 누락된 상세 스탯을 카드 종합 능력치로 대체하지 않으며 필요한 스탯이 없으면 계산을 제한합니다. EA 공식 계산 또는 PS5 실측 검증을 뜻하지 않습니다.

`npm run build`, `npm test`와 `node server.cjs --mock`으로 로컬 검증을 실행합니다. 실제 계정의 응답, 권한, 사진 제공 범위는 승인된 설정으로 별도 확인해야 합니다. 현재 소스는 `C:\fc27squad`에 있습니다. 이 폴더의 `시작.cmd`를 사용하세요. 이전 ZIP은 이전 소스 묶음입니다.


- **스탯 변경안 적용**: AI 변경안을 계산기로 열거나 직접 계산한 뒤 “내 선수에 적용하고 추천 다시 계산”을 누르면 선택한 변경안의 능력치와 주 포지션 추정 OVR를 저장합니다. 원래 선호 포지션은 유지해 사파 적합도와 커버를 분석하며, 목표 미달이면 달성한 실제 추정치만 적용합니다. POT·가격·주급을 임의로 올리지 않습니다. 기존 동적 OVR·성장 평가 기록이 적용한 스탯을 덮어쓰지 않으며, 변경된 능력치로 커버와 현재 예산·매각 설정의 영입 조합을 다시 계산합니다. 조합은 별도로 검토·적용할 수 있고, 계산에 실패해도 스탯 저장은 유지하며 재시도할 수 있습니다. “적용 전 스탯으로 복원”은 첫 적용 전 능력치를 복구하고 다시 분석합니다. 적용·복원 기록은 브라우저 저장 및 JSON 백업에서 유지되고, 실제 게임 세이브에는 반영되지 않습니다.
